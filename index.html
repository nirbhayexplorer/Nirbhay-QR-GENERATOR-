01 What this tool is

Nirbhay QR Generator is a browser-based utility that converts text or a URL into a QR code. It is developed under the Nirbhay Explorer brand by Nirbhay Gautam.

The generator is designed around three principles: it should be simple, it should be fast, and it should minimise unnecessary data transmission. The QR image you see on screen is produced by code running inside your own browser tab — there is no rendering server involved for the QR itself.

Client-side rendering

The QR matrix is computed locally and drawn onto an HTML canvas element in your browser.

No account required

All core features work without signing in. An optional Google sign-in is available.

Three export formats

PNG, JPG and SVG downloads, each produced from the same generated data.

02 How QR codes work

A QR code ("Quick Response" code) is a two-dimensional barcode. Instead of storing data in a single line of varying-width bars like a traditional barcode, a QR code stores data across a grid of black and white modules.

The grid is read by a scanner in a fixed order. Several structural elements make this possible:

  • Finder patterns — the three large square markers in three corners. They let a scanner detect the code and determine its orientation.
  • Alignment patterns — smaller squares used in larger codes to compensate for perspective distortion.
  • Timing patterns — alternating module rows and columns that help the scanner measure the grid.
  • Format and version information — metadata describing the error correction level and the code size.
  • Data and error correction modules — the actual encoded payload plus redundant data used for recovery.

Because a QR code can be read from any angle and tolerates a certain amount of damage, it is well suited to printing on posters, packaging, business cards and screens.

03 Generating your first QR code

  1. Open the QR Generator section.
  2. Type or paste your content into the Enter URL or text field. This can be a website address, a sentence, a phone number, an email address or any other text.
  3. Optionally adjust the foreground color, background color, size, margin and error correction level.
  4. Select Generate QR Code.
  5. The result appears in the QR Preview panel on the right (or below, on smaller screens).
  6. Use the download buttons to save the image, or use Copy Content to copy your original text back to the clipboard.

04 Customization

Foreground color

The foreground color is the color of the data modules — the "dark" squares. Dark colors such as near-black produce the most reliable scans across a wide range of devices.

Background color

The background color fills the light modules and the margin around the code. Light backgrounds are strongly recommended. Very light pastel tones generally still work, but pure white offers the highest reliability.

Size

Size controls the pixel dimensions of the exported image (256 px up to 1024 px). A larger export size is useful for printing; the on-screen preview is scaled to fit regardless of the chosen export size.

Margin (quiet zone)

The margin is the empty border around the QR code, measured in modules. The QR specification recommends a quiet zone of at least 4 modules for printed codes. This tool allows 0–6 so you can control the final look, but values below 2 may reduce scan reliability, especially when the code is placed on a busy background.

Error correction

Error correction determines how much redundancy is embedded in the code. Higher levels survive more damage but reduce the maximum amount of data that fits in a single code. See section 11 for details.

05 Downloading

Three export formats are available. PNG is free. JPG, SVG and the 768 px and 1024 px sizes require a Pro or Business plan. Each is generated from the same encoded content, so all three scan identically.

PNG

Lossless raster image. Best general-purpose choice for sharing, messaging apps and embedding into documents.

JPG

Compressed raster image. Smaller file size, but JPEG compression can introduce artefacts around sharp module edges. Use PNG when possible.

SVG

Vector format. Scales to any size without loss of sharpness — ideal for professional printing and design software.

Downloads are created entirely in your browser using a temporary object URL. The file is saved directly to your device by your browser's normal download mechanism.

06 History and local storage

Every time you press Generate QR Code, the content, colors, size, margin, error correction level and a timestamp are saved into your browser's localStorage under this site's origin.

  • History is local to this device and this browser. It is not synced across devices.
  • It is not sent to any server by this application.
  • Clearing your browser's site data, using private/incognito mode, or pressing Clear History will remove it.
  • Browsers typically allow around 5 MB of local storage per origin; this application also limits the number of saved entries to keep usage small.

If localStorage is unavailable — for example in some private browsing configurations — the generator continues to work normally, but history will not be saved.

07 Supported content

At its core, a QR code stores a sequence of characters. This tool encodes exactly the text you provide — nothing is added, modified or validated. Practical examples include:

  • Website links — https://example.com
  • Plain text — a note, a message, an instruction
  • Email addresses — name@example.com
  • Phone numbers — +91 90000 00000
  • Structured strings — vCard, WiFi or geo formats, provided you type the correct syntax yourself

ImportantThis generator encodes text. It does not automatically convert your input into special formats such as vCard or WiFi configuration. If a scanner does not recognise a structured string, the syntax — not the QR code — is usually the cause.

08 URL encoding

When encoding a website address, include the full scheme. A code containing example.com without https:// may be interpreted differently by different scanner applications — some will search for the term, others will try to open it as a link.

Recommended practice:

  • Always include https:// or http://.
  • Avoid unnecessary tracking parameters; they increase data size and make the code denser.
  • Shorten very long URLs where possible, since longer content produces a denser grid that is harder to scan from a distance.
  • If a URL contains spaces or special characters, they should be percent-encoded (for example %20 for a space) by the destination system.

09 Text encoding

QR codes support several encoding modes, including numeric, alphanumeric, byte and kanji. The rendering engine selects an efficient mode automatically based on your content.

For most languages and symbols, byte mode (UTF-8) is used. This means emoji, accented characters and non-Latin scripts can be encoded — however, whether they display correctly depends on the scanner application and the device's font support.

Short is safer

Fewer characters means fewer modules, a larger effective module size and better scan reliability.

Mixed scripts

Mixing scripts increases the data size. Test with a real scanner before printing.

10 Readability and contrast

A QR scanner works by distinguishing dark modules from light modules. The greater the contrast between them, the more reliably the code can be decoded.

  • Prefer dark foregrounds on light backgrounds. Inverted codes (light on dark) are not supported by every scanner.
  • Avoid mid-tone color pairs — for example blue on purple — because the luminance difference is small.
  • Never place a QR code on a patterned or busy background. Always keep the quiet zone empty.
  • Test the printed result with at least two different scanner applications before a large print run.

This application displays a warning when the contrast between your chosen colors is very low, and it will decline to generate a code when the contrast is too low to be practically scannable.

11 Error correction

Error correction adds redundant data so a scanner can reconstruct the message even if part of the code is unreadable. Four levels are available:

L — Low

Approximately 7% of the code can be restored. Fits the most data.

M — Medium

Approximately 15% recoverable. A sensible default for most uses.

Q — Quartile

Approximately 25% recoverable. Good for less controlled environments.

H — High

Approximately 30% recoverable. Best durability, smallest data capacity.

Higher error correction is recommended for codes that will be printed on surfaces that may become dirty, scratched or partially covered — for example product labels or outdoor signage.

12 Printing recommendations

  • Export as SVG for professional printing, or as a large PNG (1024 px or more) for everyday documents.
  • Print at a minimum size of roughly 2 × 2 cm for close-range scanning; increase the size for scanning from further away.
  • Maintain a clear quiet zone of at least 4 modules around the code.
  • Print on a matte surface when possible — glossy lamination can create reflections that interfere with scanners.
  • Verify the printed code with a phone camera before producing large quantities.

13 Mobile usage

The interface is designed mobile-first and works on small Android phones, including compact and budget devices.

  • The header collapses to a logo, theme control and menu button.
  • Navigation opens as a full-height glass drawer.
  • The generator stacks into a single column, with the preview below the input.
  • Downloaded files are saved to your device's default Downloads location.

On mobile, the most reliable way to test a generated code is to open the downloaded image in your gallery and scan it from another device — or display the preview on screen and scan it with a second phone.

14 Desktop usage

On larger screens the generator uses a two-column layout: controls on the left, live preview on the right. This makes it easy to iterate on colors and sizes while keeping the result visible.

Desktop browsers also make SVG export convenient: the file can be opened directly in vector software such as Illustrator, Inkscape or Figma and scaled without quality loss.

15 Troubleshooting

The QR code does not scan

  • Increase the contrast between foreground and background.
  • Increase the margin so the quiet zone is preserved.
  • Increase the error correction level.
  • Generate at a larger size and print larger.
  • Clean the camera lens and improve lighting.

Nothing happens when I press Generate

  • Make sure the input field is not empty.
  • Shorten very long content — extremely long text can exceed QR capacity.
  • If a message appears about the content being too long, shorten the text and try again.

Downloads do not start

  • Some browsers block automatic downloads. Check the download permission for this site.
  • Private browsing modes may restrict file saving.
  • Try a different browser to confirm whether the issue is browser-specific.

History disappeared

  • History is stored per browser and per device. Switching browsers or clearing site data removes it.
  • Private/incognito windows usually do not persist local storage between sessions.

16 Common mistakes

  • Using light modules on a dark background. Many scanners handle this, but not all. Prefer dark-on-light.
  • Removing the quiet zone. Cropping the code tightly to its edge is one of the most common causes of scan failure.
  • Placing the code on a photo. A busy background confuses the detection stage.
  • Encoding enormous amounts of text. The modules become tiny and the code becomes hard to capture.
  • Assuming every scanner supports every format. Structured strings such as vCard or WiFi are handled by the scanning app, not by the QR code itself.
  • Not testing before printing. Always verify with a real device.

17 Best practices

  • Keep content short and direct.
  • Use error correction level M for general use and H for harsh environments.
  • Always include a quiet zone of at least 4 modules in final artwork.
  • Export SVG for print, PNG for screens.
  • Test with iOS and Android devices before publishing.
  • For dynamic links, use a URL shortener you control so the destination can be changed later.

18 Security and privacy considerations

QR codes are simply containers for text. They do not execute code, and they cannot infect a device by themselves. The risk lies in what the encoded content points to.

  • Never scan a QR code from an untrusted source if it leads to a login page.
  • Check the destination URL in your scanner app before opening it.
  • Do not encode sensitive information such as passwords, private keys or personal identification numbers into a QR code that will be publicly displayed.
  • Remember that anyone who can see the code can read its content.

This application treats all input as plain text. Content is never interpreted as HTML or JavaScript, and it is never evaluated as code.

01 Scanning depends on the device and camera

A QR code can only be as reliable as the device reading it. A perfectly generated code may still fail on a low-resolution camera, a dirty lens, a scratched lens cover, or in poor lighting.

Older budget phones — and particularly their front cameras — often struggle with dense QR codes. Testing on the actual target audience's devices is strongly recommended.

02 Extremely long content affects complexity

QR codes have a finite data capacity. As content grows, the number of modules grows with it, and each module becomes physically smaller for the same printed size. This makes the code harder to capture.

  • Short URLs and short sentences scan reliably at small sizes.
  • Long paragraphs may produce a code that is difficult to scan from more than a few centimetres away.
  • Beyond the maximum capacity of the chosen error correction level, generation will fail and an error message will be shown.

03 Low contrast reduces reliability

Color combinations with low luminance contrast — for example dark blue on black, or light yellow on white — can render a QR code unreadable even though it looks fine to the human eye. The application warns about low-contrast combinations and blocks generation when contrast is critically low, but it cannot account for every scanner's image processing.

04 Damaged QR codes may fail

Error correction allows a scanner to recover data when part of a code is obscured or damaged. The recovery capacity is limited to the level you selected (roughly 7%, 15%, 25% or 30%).

Once damage exceeds that threshold, the code becomes unreadable. A torn label, a deep scratch, a sticker covering a corner, or heavy water damage can all exceed the correction capacity.

05 Browser limitations

The application requires a modern browser with support for:

  • HTML canvas (used for the preview and PNG/JPG export)
  • JavaScript modules
  • Local storage (for history and theme preference)

Very old browsers, or browsers with JavaScript disabled, will not be able to run the generator. Some privacy-focused browser configurations disable local storage entirely, in which case history will not persist. The QR engine itself is embedded in the page and does not require any external resource to operate.

06 Local storage limitations

  • Storage is limited (typically around 5 MB per origin) and is shared with other data on the same domain.
  • Data is per browser and per device — it does not sync.
  • Clearing browser data, using private browsing, or changing devices will remove or hide your history.
  • There is no export or backup feature for history.

07 Download format limitations

PNG

Lossless, but a fixed pixel resolution. Scaling up beyond the exported size will make it blurry.

JPG

Compressed. Sharp QR edges can develop artefacts, particularly at lower quality settings.

SVG

Vector, but depends on the receiving software supporting SVG rendering correctly.

08 Large sizes may affect performance

Generating a QR code at 1024 × 1024 pixels requires more memory and processing time than a smaller export. On low-end mobile devices this may cause a short delay. If you experience sluggishness, choose a smaller export size — the displayed preview remains readable regardless.

09 SVG compatibility differences

SVG is a vector format, and different applications render SVG files with slightly different levels of support. Most modern browsers, design tools and print workflows handle it correctly, but some older software may not. If an SVG fails to open, exporting as a high-resolution PNG is a reliable alternative.

10 Printing quality considerations

QR readability after printing depends on much more than the digital file: printer resolution, ink bleed, paper texture, lamination, lighting conditions and the physical size all play a role. A code that scans perfectly on screen can still fail on paper if it is printed too small or on a low-quality printer.

11 No guarantee that every scanner supports every configuration

Scanner applications vary widely. Some handle inverted colors, some handle very dense codes, and some attempt to be helpful by guessing whether content is a URL. There is no way to guarantee that every scanner application on every platform will handle every possible QR configuration correctly.

Always validate critical QR codes with the specific devices and applications your audience is likely to use.

12 No tracking, no dynamic links, no editing after export

This tool produces static QR codes. Once a code is generated and downloaded, its content is fixed permanently. There is no redirect layer, no click tracking and no way to change the destination later.

If you need an editable or trackable destination, use a URL shortener or link management service that you control, and encode that link instead.

Nirbhay QR Generator is a browser-focused QR creation tool developed under the Nirbhay Explorer brand by Nirbhay Gautam. It was built around a simple idea: creating a QR code should not require an account, a server round-trip, or a complicated interface.

Privacy-conscious

Modern

A clean, responsive interface that adapts from small phones to large desktop monitors.

User-friendly

Clear labels, helpful warnings and keyboard and screen-reader friendly controls.

Honest

Limitations are documented openly rather than hidden. No features are claimed that are not implemented.

03 What is implemented

  • Client-side QR generation with adjustable foreground and background colors, size, margin and error correction.
  • Download as PNG, JPG and SVG.
  • Copy content, regenerate and clear actions.
  • Recent history saved in the browser's local storage, with restore and delete.
  • Light, dark and system theme modes with saved preference.
  • Optional Google sign-in through Firebase Authentication.

Nothing beyond this list is claimed. There is no cloud sync, no dynamic QR redirect service, no analytics dashboard and no third-party tracking.

The tool is useful for anyone who needs a QR code quickly: students sharing resources, small businesses printing menu or payment links, developers embedding codes in documentation, event organisers, and anyone who simply wants a clean QR image without signing up for a service.
